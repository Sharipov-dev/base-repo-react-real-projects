<objective>
Extend the customer-create backend path so it can optionally create a Primary Contact
(`customer_contacts` row, `isPrimary: true`) atomically with the customer.

Purpose: Deliver decisions D-01/D-02/D-03/D-05/D-06/D-07 on the backend — a single
`POST /api/customers` request carries an optional `primaryContact` payload; when the
required set (firstName + lastName + email) is present the contact is created in the
same transaction as the customer; when absent the customer is created normally; when
partial the request is rejected with a 400.

Output: Updated `createCustomerSchema`, `CreateCustomerData` domain type, and a
transactional `PrismaCustomerRepository.create()`. The pass-through
`CreateCustomerUseCase`, `customer.controller.ts`, `customer.routes.ts`, and
`container.ts` need NO changes — the extended DTO flows through unchanged and the
`$transaction` lives in the repository (the `prisma-receipt.repository.ts` precedent
that D-07 sanctions). Placing the transaction in the repository also keeps
`CustomerMapper` in the infrastructure layer, honoring the backend rule that the
application layer never imports infrastructure.
</objective>

      const record = await this.prisma.$transaction(async (tx) => {
        const customer = await tx.customer.create({
          data: {
            name: data.name,
            alias: data.alias ?? null,
            phone: data.phone ?? null,
            fax: data.fax ?? null,

            zip: data.zip ?? null,

        });

        if (data.primaryContact) {

              lastName: data.primaryContact.lastName,
              email: data.primaryContact.email,
              phone: data.primaryContact.phone ?? null,
