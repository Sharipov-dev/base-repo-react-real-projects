# Автономный воркфлоу — как ставить задачи и запускать

Короткая шпаргалка: как оформить список фич и отдать их Claude на автономное выполнение через GSD.

---

## Модель в двух словах

- **`ROADMAP.md`** = план **текущего милстоуна** (пачка связанных фич). Это НЕ каталог всего приложения — он короткий и периодически чистится.
- **Фаза** = одна задача/фича с целью и критериями готовности.
- `skip_discuss: true` уже включён в `.planning/config.json` → автономный режим не задаёт grey-area вопросов, **спекой служит описание фазы**.

> ⚠️ Раз discuss пропущен — качество результата держится на качестве описания фазы. Чем конкретнее, тем меньше агент угадывает.

---

## Шаг 1. Оформить фичи как фазы

Добавить фазу в текущий роадмап:

```
/gsd-phase
```

Или, если начинаешь новую большую пачку фич с чистого листа:

```
/gsd-new-milestone
```

### Как писать описание фазы (важно!)

Каждая фаза должна содержать 4 блока. Плохое описание = агент угадывает; хорошее = делает то, что нужно.

```markdown
## Phase NN: <короткое имя фичи>

**Goal:** Одно-два предложения — что должно работать после фазы,
с точки зрения пользователя.

**Problem being solved:** Что сейчас не так / чего не хватает.
По возможности с указанием файлов (path:line), чтобы агент не искал.

**Success criteria:**
- Конкретный проверяемый результат 1
- Конкретный проверяемый результат 2
- Что НЕ должно сломаться (регрессии)

**Requirements:**
- REQ-XX-01 — атомарное требование
- REQ-XX-02 — атомарное требование
```

**Правила хороших фаз:**
- Одна фаза = одна связная фича, а не «сделать всё приложение».
- Success criteria — проверяемые (можно ткнуть и убедиться), а не «улучшить UX».
- Указывай файлы/модули, если знаешь где — экономит агенту время и снижает ошибки.
- 3–8 фаз на милстоун. Больше — разбей на два милстоуна.

---

## Шаг 2. Запустить автономный режим

Все незавершённые фазы подряд:

```
/gsd-autonomous
```

Только диапазон фаз:

```
/gsd-autonomous --from 3 --to 5
```

Одну фазу:

```
/gsd-autonomous --only 4
```

Что делает: для каждой фазы гоняет **plan → execute** (discuss пропущен),
после каждой обновляет `STATE.md` / `ROADMAP.md`, коммитит атомарно.

---

## Шаг 3. Где он всё-таки остановится

Даже в автономном режиме GSD паузится на настоящих развилках (не серые вопросы):

- **Blocker** — фаза упала → retry / skip / stop.
- **Gap closure** — верификация нашла незакрытые дыры.
- **Milestone audit** — расхождение с задумкой.
- **Cleanup** — подтверждение удаления файлов.

Это by design — там реально нужен человек. (Если захочешь полный zero-pause —
можно повесить хук, который авто-выбирает рекомендованный вариант; но на блокерах
он будет слепо жать retry, есть риск зацикливания.)

---

## Шаг 4. Закрыть милстоун и начать заново

Когда все фазы готовы:

```
/gsd-complete-milestone   # архивирует готовый милстоун
/gsd-cleanup              # убирает папки завершённых фаз
```

После этого `ROADMAP.md` чистый → начинаешь следующую пачку фич с Шага 1.

---

## Типовой цикл (TL;DR)

```
1. /gsd-phase              → добавить фичи как фазы (детальные описания!)
2. /gsd-autonomous         → запустить и уйти
3. (агент паузится только на реальных блокерах)
4. /gsd-complete-milestone → /gsd-cleanup
5. → назад к шагу 1 с чистым роадмапом
```

---

## Полезные команды рядом

| Команда | Зачем |
|---|---|
| `/gsd-progress` | Где я сейчас, что дальше |
| `/gsd-phase` | Добавить/изменить/удалить фазу |
| `/gsd-resume-work` | Продолжить после паузы/перезапуска |
| `/gsd-stats` | Статистика: фазы, планы, таймлайн |
| `/gsd-settings` | Тумблеры воркфлоу (в т.ч. skip_discuss) |
