<objective>
Make the frontend permission-aware. Fetch the current user once (server-side via /api/auth/me),
expose `can(key)` through a client provider, gate the sidebar nav, and replace raw 403s for
non-active users with a friendly "awaiting activation" screen.

Purpose: Today the FE does zero status/role/permission gating and shows raw `403 Account pending`
text. This plan adds the gating substrate (provider + can helper) and the two most visible UX
fixes: nav gating and the pending screen.
Output: a `shared/auth` provider + hook + status screen, a `modules/auth` current-user API, and
wiring into the protected layout + Sidebar.
</objective>
