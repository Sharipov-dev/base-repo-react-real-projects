<objective>
Wire CSV/Excel export onto the Inventory and Inventory Transactions DataTables. Both are
INLINE-TYPED (rendered without an explicit `<DataTable<T>>` generic; columns typed as
`ColumnDef<typeof rows[number]>`), so `handleExportAll` must return the same row type the
list API produces (or add an explicit generic) to keep TS strict happy. Both use server-side
filters the all-records page-loop MUST thread (Inventory: `search`; Transactions: `type`)
per the LOCKED filter decision. Dates are ISO `string`.

Transactions' `inventoryId` is shown truncated. The `InventoryTransaction` UI model carries
ONLY `inventoryId` (a string) — it does NOT carry `itemSku`/`itemName` or any item label
(verified against `inventory/model/types.ts`). Per the LOCKED FK decision the export must show
a human-readable label, so resolve `inventoryId` → `"<itemSku> — <itemName>"` via a lookup
Map built from `listInventory` (whose rows DO carry `id`, `itemSku`, `itemName`), mirroring
plan 02-02's `listRoles`/`resolveRoleName` pattern. Fall back to the FULL (untruncated)
`inventoryId` when the id is not in the map — never export the `.slice(0,8)` display value.

Purpose: Extend export to the two inventory tables (the inline-typed + FK-label-via-lookup cases).
Output: Two modified table components; transactions inventoryId exports a readable label.
</objective>
